# 3단계 — 검증 체계 자체

> **기준 커밋**: `ef4e8d3` · 0단계에서 질문을 바꿔 둔 판이다 —
> *"도구가 맞나"*(표본 3/3 검출로 이미 확인)가 아니라 **"무엇을 안 보나 · 언제 도나"**.

## 1. 회귀 골든이 보지 않는 것 — F-011 `[실측]`

골든은 42케이스 × 최대 32지표지만, **어떤 코드 경로를 밟느냐**가 실제 커버리지다.

```
골든이 명시적으로 켜는 토글           40개
EFFECT_ALIVE(효과 확증된 토글)        43개
그중 골든이 안 켜는 것                16개
  ├ 기본 True (ON 만 감시, OFF 대조 없음)  5: cec_preassign · munition_limit ·
  │                                          ship_evasion · standoff_spawn · subsystem_damage
  └ 기본 False (아예 안 밟음)             11: asw_forward · autonomous_engagement ·
        battle_mode · campaign_fog · cec_jammed · laser_dew · minesweeping ·
        multibearing · random_placement · ras_rearm · recon_drone
```

**11개 중 다수가 기준값 메모리로 검증을 마친 기능이다**(RAS 재보급 · 정찰 드론 ·
자율 교전 · 기뢰전 · 레이저). **검증은 했는데 그 결과를 지키는 장치가 없다** —
기준값은 사람이 읽는 메모리에 있고, 기계가 읽는 골든에는 없다.

`audit_effect.py` 가 대신 보지 않느냐는 반론은 성립하지 않는다. 그것은 **같은 실행 안에서
ON/OFF 델타 ≠ 0** 만 본다. *"효과가 있다"* 는 지키지만 *"결과가 이전과 같다"* 는 안 본다.

> B단계 설계의 약점 **나**(*"회귀 PASS 는 안 깨뜨렸다의 증거가 아니다"*)에 대한
> **이 저장소의 구체적 실측 증거**다. 영향 반경이 회귀를 소환해도, **회귀가 보는 범위 밖**이면
> 소용이 없다. → F-011

## 2. 골든 지표의 변별력 `[실측]`

케이스 간 고유값이 1이면 그 경로는 한 번도 안 도는 것이다.

| 고유값 1 (감시 0) | 상태 |
|---|---|
| `iff_failures` · `iff_fratricide` | `chk_golden_coverage` 의 `KNOWN` 에 의도 등재 · [[project-experimental-promotion]] 의 *"IFF 미검증 보류"* 를 데이터가 뒷받침 |
| `usa_cost` · `usa_shots` | 한국 단독 시나리오라 의도된 사각 |

**검사는 vacuous 가 아니었다** — 이 넷을 이미 알고 화이트리스트로 관리한다.
다만 **화이트리스트가 낡았다**: `ashore_sm3_fired`(고유값 4)·`thaad_fired`(2)는
이미 변별되는데 면제 목록에 남아 있다 → **F-010**.

## 3. "아무것도 검증하지 않는 검사" 사냥 — 결과: **없음** `[실측]`

규약 2.3-3 의 대상. 먼저 크게 훑고(`check(`·`assert` 계수), 그다음 **표본을 직접 읽었다**.

| 1차 휴리스틱 | 실제 |
|---|---|
| `_audit_campaign_smoke` 검사 0 · `except` 10 → vacuous 의심 | ❌ **오판** — `return 1` + 🔴 로그로 판정한다(배너 미표시 10종 검사). 예외는 UI 조작 실패용이고 그 경우 배너가 안 떠 **fail-closed** |
| `audit_property` 검사 1 → 얕음 의심 | ❌ **오판** — 자체 **vacuous 가드**가 있다(L205~209: 단발 총위협 합 0이면 *"검사 무력화"* 로 violation) |

> 또 계수 휴리스틱에 속았다(이 판에서만 세 번째). **도구의 판정 신호는 `check()` 만이 아니다**
> — `return 1` · `sys.exit(1)` · 🔴 문구를 함께 봐야 한다.

**판정 신호가 아예 없는 것 2개**: `audit_db_consistency` · `audit_dead_toggle` 은
FAIL 문구만 찍고 **exit 0** 이다. 코드에 *"각 항목은 사람이 판정(의도된 설계일 수도 있다)"*
이라 명시돼 있어 **의도된 보고 도구**다 — 결함 아님.
→ 다만 **F-003(훅 배선) 실행 시 이 둘은 제외해야 한다.** 배선하면 항상 통과하는
게이트가 된다. F-003 에 단서로 기록.

## 4. 미검토 상태로 쌓여 있는 발견 `[실측]`

`audit_db_consistency.py` 를 이 판에서 실행하니 **발견 6건**이 나왔다(수동 도구라 아무도
안 돌리면 안 보인다 — F-003 의 실물):

```
🔴 [HIGH] 마하표기↔속도  Tu-22M3 탑재 Kh-32 '극초음속'인데 1500 m/s(마하 4.4) < 마하 5
🟠 [MED ] 무기사거리↔탐지 × 4  (최대 탐지 415km < Kalibr 발사거리 1350km → 끝까지 안 보인다)
```

**2-A(물리·DB) 판의 입력**으로 넘긴다. 여기서 판정하지 않는다 — 의도된 단순화일 수 있고
(규약 4.5), 그 판단은 DB 제원 대조와 함께 해야 한다.

## 5. 이 판의 순수익

- **중간 2건**(F-010 화이트리스트 stale · F-011 골든 미커버 11토글)
- F-003 에 단서 1건 추가(보고 도구는 훅 배선 대상이 아니다)
- 2-A 로 넘긴 입력 1건(DB 정합 6건)
- **vacuous 검사는 찾지 못했다** — 이 저장소의 감사 도구는 실제로 판정한다.
  대신 문제는 **범위**(무엇을 안 보나)와 **주기**(언제 도나)였다. 0단계에서 질문을
  바꾼 것이 맞았다.
