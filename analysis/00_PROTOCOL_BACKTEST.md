## 2. 적대적 테스트 — 규약을 통과하면서 나쁜 짓 하기 `[실측]`

논증이 아니라 **실제로 뚫어 본** 결과다. 1라운드에서 4개가 뚫렸다.

| 공격 | 1라운드 | 막은 방법 | 현재 |
|------|:------:|-----------|:----:|
| 예측 크기를 `최소 0%p` 로 | **뚫림** | `ZERO_MAG_RE` — 0은 예측이 아니다 | 막힘 |
| `MC 200회` 의 200을 크기로 오인시키기 | **뚫림** | 크기 단위에서 표본수(`회`) 제외 | 막힘 |
| 노이즈 이하 예측(`최소 2%p`, 시드 산포 ±4.0%p) | **뚫림** | 고정 seed 결정론 대조 또는 표본수+산포 명시 의무 | 막힘 |
| 판정 문자열 위조(`재현: chk_추후에만들것`) | **뚫림** | `chk_` 가 감사 도구에 **실제 정의**돼 있는지 대조 | 막힘 |
| 없는 프로브 경로만 적기 | 뚫림 | 파일 존재 확인 | 막힘 |
| 예측을 **코드 뒤에** 끼워넣기 | 뚫림 | 도입 커밋이 코드 커밋의 **조상**인지 `merge-base` 로 확인 | 막힘 |
| 예측을 사후에 **고쳐 쓰기** | 뚫림 | 같은 조상 검사에 걸린다(고친 문자열의 도입 커밋이 뒤가 됨) | 막힘 |

## 3. 이 대조로 새로 굳힌 것

1. **`chk_global_name_import`** (`audit_static_scan.py`, 정적 54→56항목)
   — 재할당 전역(`global X`)을 `from mod import X` 하는 것을 금지. 과거 실제 결함 형태
   (`from app_utils import _GLOBAL_POOL`)를 주입해 **FAIL로 잡히는 것을 확인**하고 복구했다 `[실측]`.
   이 저장소가 **두 번 당하고도** `CLAUDE.md`의 "옮기기 전에 grep 하라"는 **사람 규칙으로만**
   남아 있던 자리다.
2. **`짝:`·`무대:` 필수 필드** — 발현 증거 3종 중 내가 빠뜨렸던 둘을 대장에 되살렸다.
3. **판정의 실재·선행성 검사** — 적어만 두고 안 만드는 것, 사후에 끼워넣는 것을 차단.
4. **훅 배선** — 규약이 "돌리기로 한 것"에서 "안 돌리면 커밋이 안 되는 것"이 됐다.

## 3-b. 4라운드 — 도구 자신을 찔러서 나온 것 `[실측]`

규약이 아니라 **검사기를 대상**으로 다시 찔렀다. 셋이 나왔고 전부 실제 결함이었다.

| # | 찌른 것 | 나온 결함 | 조치 |
|---|---------|-----------|------|
| 1 | 반경 표가 저장소를 덮나 | **엔진·워커가 실제로 import 하는 모듈이 표에 없었다** — `engine_combat`→`db_terrain`, `engine_campaign`→`forecast_features`, `app_workers`→`ai_policy_infer`. 이 파일들을 고치면 회귀가 **소환되지 않았을** 것이다 | 표 보강 + 추적 파일 **282개 전부 분류** 확인 |
| 2 | 한글 경로(`변경이력/` `감사보고서/`) | git 이 기본값(`core.quotepath=true`)으로 `"ë³…"` octal 을 내보내 **선언 대조가 조용히 어긋난다** | `_git` 에 `-c core.quotepath=false` |
| 3 | 검사기가 예외를 던지면 | pre-commit 에 물려 있어 **저장소 전체 커밋이 traceback 으로 막힌다** | 예외를 FAIL 로 흡수(`audit_static_scan` 관례) |

> 1번이 특히 중요하다. 반경 표를 **이름만 보고** 짰기 때문에 생긴 것으로,
> 표는 **소스의 import 로 검증**해야 한다. "미분류는 FAIL"이라는 안전 기본값이 없었다면
> 이 셋 다 조용히 지나갔을 것이다.

## 3-c. 5라운드 — 절차를 **끝까지 한 번 돌려봤다**(모의 묶음) `[실측]`

부품 단위 테스트로는 안 나오는 것을 찾으려고, 임시 저장소에서 **B 묶음 하나를 규약대로
처음부터 끝까지** 진행했다(선언 → 코드 수정 → 결과 기입 → 사후 조작 시도).

| # | 나온 것 | 성격 | 조치 |
|---|---------|------|------|
| a | **규약을 정확히 지켰는데 선행성 검사가 FAIL** — 대상 파일의 *전체 과거 이력*(파일 생성 커밋까지)과 비교하고 있었다 | **치명 오탐** | 비교 대상을 **이 묶음의 코드 커밋**(메시지에 `F-0NN`)으로 한정 |
| b | 고친 줄의 **앵커 불일치가 FAIL** → B단계의 **모든 수정이 커밋 불가** | **치명 오탐** | `수정중`/`수정됨` 항목은 경고로. 묶음 닫을 때 앵커 갱신 |
| c | 9.1 *"한 묶음 = 한 커밋"* 인데 9.2 는 *"예측을 코드 전에 문서만 커밋"* | **내부 모순** | 한 묶음 = **선언 커밋 + 묶음 커밋 2개**로 명시. 묶음 커밋 제목의 `F-0NN` 이 기계적 의미를 갖게 됨 |
| d | 9.4 ③ 이 *"골든이 바뀌었으면"* 만 다룬다 | **사각 누락** | ④ 신설 — 반경 E·C 인데 골든이 **하나도 안 바뀌면** 무대 부재 신호(레이저 v17.2) |

**재실행 결과**: ①선언 OK → ②코드 수정 경고 1(앵커 이동 안내) → ③결과 기입 OK →
④예측 사후 조작 **FAIL 유지**. 오탐은 사라지고 방어는 살아 있다.

> 교훈: **부품을 다 테스트해도 절차를 안 돌려보면 모른다.** a·b는 규약을 성실히
> 따르는 사람만 만나는 오탐이라, 실전에서 만났으면 *"검사기가 이상하니 `--no-verify`"* 로
> 이어졌을 것이다 — 규약 전체가 무력화되는 경로다.

## 4. 이 대조 뒤에도 남는 것 (정직하게)

- **내용 판단은 기계가 못 한다.** `짝: 없음`·`무대: 적정 편성`·무관한 URL은 형식을 통과한다.
  4번 사건이 ⚠인 이유다. 완화책은 무대에 **수치가 없으면 경고**하는 것뿐이다.
- **R의 예측을 내가 쓴다** — 맞히기 쉬운 예측만 고르는 편향은 기계 밖이다.
- **반경 표 stale** — 새 파일은 미분류 FAIL로 *새는 것*만 막는다. 분류의 타당성은 사람이 본다.
- **pre-push 비용 `[미확인]`** — 첫 묶음에서 측정해 9.5를 갱신할 것.
- **`--no-verify`** 로 훅을 건너뛰는 것은 의도적 회피라 규약 범위 밖이다.
