# 2-B단계 — 지표·집계 정의의 정합

> **기준 커밋**: `efd5c44` · 규약 2.2 **D**(0단계 캘리브레이션에서 신설한 축).
> 2-A(물리 수식·확률 합성·단위)는 별도 판. 여기서는 **무엇을 세고 무엇을 안 세는가**만 본다.

## 0. 먼저 틀린 것부터 — F-004 오탐

이 판은 *"`_compile()` 1,802줄에 지표 정의가 몰려 있다"* 는 0단계 결론에서 출발했는데,
**그 측정이 틀렸다.** AST 로 재보니 `_compile()` 은 13줄(`BattleEngine`)·109줄
(`TimeStepEngine`)이고, 최장 메서드는 `_build_enemies` 237줄이다.
정규식이 메서드 끝을 *"다음 4칸 `def`"* 로 잡았는데 그 뒤는 모듈 수준 함수였다.
→ F-004 를 **오탐**으로 종결하고 0단계 문서를 정정했다. **라인수는 AST 로 잰다.**

판의 목적 자체는 유효했다 — 지표 정의는 한 함수가 아니라 **여러 경로에 흩어져** 있고,
바로 그 흩어짐이 이 판의 발견을 만들었다.

## 1. 32지표 쓰기 지점 전수 `[실측]`

두 번째 계측 실수도 있었다: 첫 스캔이 `+=` 를 놓쳐 *"갱신처 없음"* 이 대량으로 나왔다.
패턴을 `(\+=|=)` 로 고쳐 다시 뽑았다.

| 쓰기 지점 수 | 지표 |
|---|---|
| **4곳** | `total_threats`(2172·2306·3138·3179) · `intercepted_threats`(3984·5122·5233·5245) · `friendly_hits` |
| 2곳 | `t_first_fire` · `total_missiles_fired` |
| 1곳 | 나머지 대부분 (`_compile` 내 집계) |
| 파생(쓰기 없음) | `intercept_rate` · `neutralization_rate` · `sim_time` · `total_channels` |
| **엔진 밖** | `n_alive_ships` · `n_alive_threats` · `n_threats_total` — **감사 도구가 계산**한다(`audit_verify_regression.py:267~269`) |

분자 4곳은 전부 미사일류(SAM 요격 · 아음속 격추 · 기만기 어뢰 회피 · 회피 기동)로
**일관**한다. 문제는 분자가 아니라 **분모**다.

## 2. 분모의 경로 의존성 — F-005 → F-008 `[실측]`

```
L2172 초기 편성:  if(미사일) → total_threats += 1     (else 의 플랫폼은 안 센다)
L2306 파도 스폰:  if/else 밖  → total_threats += 1     (플랫폼도 센다)
L5674 무력화율 :  _n_tot = total_threats + suicide_threats
```

같은 자폭 플랫폼이 **초기 편성이면 분모 기여 1, 파도 스폰이면 2**가 된다.

프로브 `analysis/probes/p008_denominator_double_count.py` 로 재현:

| 실행 | total | suicide | 무력화율 |
|---|---:|---:|---|
| 파도 없음 | 32 | 20 | **0.6731** (35/52) — 정당 |
| `ai_tactic='stagger'` | 56 | 32 | **0.2841** (25/88) — 이중 |

차이 **24 = 편성 객체 수(12+8+4)와 정확히 일치** → 플랫폼이 분모에 들어간 증거다.

> `is_suicide_platform` 의 docstring(L1259)은 *"두 곳이 갈리면 지표가 거짓말을 한다"* 고
> 경고하며 술어를 한곳에 모았다. **경고는 맞았고 위치가 틀렸다** — 갈린 곳은 술어가 아니라
> **분모 합성**이었다.

## 3. 곁가지로 나온 엔진 버그 — F-009 `[실측]`

분모를 재현하려고 `stagger` 를 켰다가 **적 전력이 늘어나는 것**을 봤다.


UI 정규 옵션 **"시차 공격"**(`mixin_configpanel.py:1459`)이다. *도착 시점을 흩는* 전술이
*전력을 늘리는* 전술이 돼 있다. **수정은 한 줄.**

# 2-A단계 — 물리 수식 · 확률 합성 · 단위

> 2-B 와 같은 파일에 이어 쓴다(같은 축의 두 판).

## 1. 확률 합성 `[코드]`

| 점검 | 결과 |
|------|------|
| 독립 가정 남용(`1-(1-p)^n`) | **0곳** — 이 엔진은 독립 합성을 안 쓴다. 층별로 1발씩 배정하고 각각 독립 판정 |
| 확률 덧셈 | 0곳(검출된 2건은 `sim_seed` 산술, 확률 아님) |
| 확률 곱 | 4곳 — 전부 clamp 또는 단조 감쇠(`exp(-d/scale)`) |
| `[0,1]` clamp | **35곳** — `min(1.0, …)`·`max(0.0, …)` 로 방어 |

**핵심 검산 — `pk_base` 제자리 변형이 복리로 누적되는가**: ❌ **아니다.**

```
L5209 ECM        m.pk_base = max(0.0, m.pk_base * (1.0 - 0.30*scale))
L5216 좌표 기만   m.pk_base = m.pk_base * exp(-miss_d / _DECEPTION_SCALE_M)
L5221 사이버 교란 m.pk_base = max(0.0, m.pk_base * _CYBER_JAM_PK)
```

셋 다 미사일 객체의 속성을 **덮어쓰지만**, 이 블록은 `_check_hits` 안이고
`L5149  if not m.hit or not m.alive or m.intercepted: continue` +
`L5152  m.alive = False` 로 **미사일당 정확히 한 번**만 지난다. 틱마다 곱해지지 않는다.

> 다만 지역변수 대신 객체 속성을 고치는 형태라 **다른 호출자가 생기면 즉시 복리 버그**가 된다.
> 지금은 맞지만 구조가 위태롭다 — 4단계 부채 목록에 남긴다.

**표적 난이도 계수의 이중 계상 방어** `[코드]`: `_target_difficulty` 의 속도 계수는
탄도·HGV 를 **명시적으로 면제**한다(L3405~3410). *"SM-3·THAAD 의 Pk 는 애초에 마하 10급
탄도를 상대로 매긴 값이라 속도 페널티를 또 곱하면 이중 계상"* — 논증이 옳고 코드도 일치한다.
RCS 계수는 상한 1.0 으로 잘라 **하위 호환 방향**(기존보다 잘 맞는 일이 없게)으로 설계했다.

## 2. 단위 경계 `[실측]`

| 경계 | 결과 |
|------|------|
| km ↔ m | 50곳 — 전부 `_km * 1000` / `_m / 1000` 관용형. 혼선 없음 |
| USD | 엔진은 **raw USD** 로 저장하고(`total_cost` 133,290,000.0) 표시 계층만 `/1e6` + `M$` 라벨. **일관** |
| kts ↔ m/s | 엔진에 환산 상수가 없다 — DB 가 **m/s 로만 저장**하고 kts 는 주석에만 있다. 혼선 구조적으로 불가 |
| s ↔ ms | 변환 0곳 — 시간은 초 단위로 통일 |

**단위 결함 0건.** 이 프로젝트는 단위를 한 단위계로 강제해 두어 그 부류가 아예 없다.

## 5. 못 한 것 (정직하게)

- **2.2C 왜곡의 크기(ON/OFF MC 실측)** — `미측정`. 근사 하나당 MC 2회가 필요해 이 판의
  범위를 넘는다. 규약대로 **추정치를 적지 않는다.** `audit_effect` 가 고정 seed 단발로
  델타를 재고 있으므로, 크기 측정은 **B단계에서 R형식 예측과 함께** 하는 것이 효율적이다.
- **물리 수식 전수 표화** — 소나(Mackenzie·Thorp)·ISA·지형은 출처 주석이 달려 있어
  *"어떤 가정이 깔렸나"* 를 문서로 옮기는 작업이 남았다. 이 판에서는 **결함을 찾는 쪽**에
  시간을 썼고 표화는 안 했다. 5단계에서 *남은 일*로 기록한다.
