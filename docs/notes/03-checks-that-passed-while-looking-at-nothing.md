# 아무것도 안 보면서 통과한 검사들

> 합동 통합방어 시뮬레이터 · 2026-09-05 · [`3f509c7`](https://github.com/yim2412/joint-defense-sim/commit/3f509c7) · [`e12db7d`](https://github.com/yim2412/joint-defense-sim/commit/e12db7d)

이 프로젝트는 검사가 많다. 정적 스캔 51항목, 회귀 38×29, 불변식 property, 토글
round-trip 44개, 효과 프로브, 커밋마다 도는 pre-commit, 푸시마다 도는 pre-push.
초록이 잔뜩 뜬다.

그런데 네 번, **서로 다른 방식으로** 검사가 아무것도 보지 않은 채 통과했다.
네 건 다 초록이었다.

## ① 순회 대상이 0개였다

GUI 탭을 클릭해서 크래시를 잡는 자동화를 붙였다. Windows 접근성 API 로 탭을 찾아
하나씩 눌러 보는 방식이다.

돌리면 통과했다. 순회한 탭이 **0개**였기 때문이다.

이 앱은 탭을 커스텀 스타일 위젯으로 그린다. 접근성 트리에 `TabItem` 으로 노출되지
않아서, 찾는 쪽이 빈 목록을 받았다. 빈 목록을 순회하면 실패가 나올 수 없다.

```python
for tab in find_tabs(window):   # ← 0개
    click(tab)                  # 한 번도 안 돈다
# 예외 없음 → PASS
```

접근성 API 로는 근본적으로 안 되는 것이라, 방식을 바꿨다 — 탭을 클릭하는 대신
**차트 렌더 함수 9개를 헤드리스로 직접 호출**했다. 실제 데이터와 엣지 데이터로.
클릭 순서에 얽힌 상호작용 버그는 여전히 못 잡지만, **못 잡는다는 것을 아는 상태**가
됐다.

그리고 이 유형을 일반적으로 막는 장치를 넣었다.

```python
guard_count('①', '엔진 소비 플래그', len(consumed), 40)
# 추출 결과가 하한보다 적으면 그 검사 자체를 FAIL 시킨다
```

**0개를 추출하고 조용히 통과하는 것**이 이 프로젝트에서 가장 자주 나온 실패 모양이라,
검사마다 "최소 이만큼은 나와야 한다"를 박았다.

## ② 골든에 그 편성이 아예 없었다

ARM 회피 전술의 게이트를 고쳤다. 레이더 침묵이 미사일 명중 시점과 어긋나 있던 것을
바로잡은, 동작이 확실히 바뀌는 수정이었다.

회귀를 돌렸더니 **38개 케이스 × 29개 지표가 전부 bit-identical PASS** 였다.

동작을 바꿨는데 회귀가 안 깨진다면 둘 중 하나다. 수정이 아무 효과가 없거나,
**회귀가 그 경로를 안 밟거나.** 후자였다 — 골든 케이스 어디에도 ARM 을 든 편성이
없었다. 없는 무기의 회피 전술을 고쳤으니 결과가 같을 수밖에.

케이스를 추가하고(30→32) 다시 걸었다.

이게 처음이 아니었다. 감사 기록에 *"감사에서 반복된 패턴"* 이라고 적혀 있다.
같은 모양을 또 만난 적이 있는데, CAP 전투기가 대잠 순회에 잘못 들어가 무장 조회에서
`KeyError` 로 죽는 버그였다. 시나리오는 있었는데 **코드 경로가 안 밟히고 있었다.**
그때 남긴 교훈이 이거다.

> **"시나리오는 있으나 코드 경로가 안 밟히는" 사각은 골든 케이스 추가로만 닫힌다.**

## ③ 게이트의 스캔 범위 밖이었다

검증 없이 태어나는 죽은 기능을 막으려고 커밋 게이트를 만들었다
([01번 노트](01-a-gate-that-only-checked-nothing-broke.md)). 엔진이 소비하는 신규
토글에 효과 프로브가 없으면 커밋을 막는다.

그 게이트가 `engine_combat.py` **한 파일만** 스캔했다.

그런데 이 앱은 그 사이에 작전급 캠페인·공군·육군·합동 층이 붙어 파일이 다섯이 됐다.
`enable_joint_fires`·`enable_air_campaign`·`enable_sead`·`enable_amphibious` 같은
**캠페인 층 토글 11개가 전부 자동 면제**되고 있었다. 스캐너가 그 파일들을 안 읽으니
"소비되지 않는 토글"로 보였고, 소비되지 않으면 커버를 요구하지 않는다.

**부채 43개를 만든 바로 그 구멍이, 새로 생긴 층에는 그대로 열려 있었다.**

```python
# 전
ev = rd('engine_combat.py')
# 후
ev = (rd('engine_combat.py') + rd('engine_campaign.py') + rd('engine_airforce.py')
      + rd('engine_army.py') + rd('engine_joint.py'))
```

한 줄짜리 수정인데, 켜는 순간 11개가 미커버로 FAIL 하므로 프로브 9개를 먼저 만들어야
했다. 게이트를 넓히는 비용은 게이트 코드가 아니라 **그 안에 들어오는 것들** 쪽에 있다.

## ④ 스캐너가 읽는 파일 목록이 낡았다

`app_main.py` 를 12,808줄에서 1,745줄로 쪼갰다. 계층 16개, mixin 6개로.

정적 스캐너에는 향후 계획 목록(`_PLANS`)이 낡았는지 보는 검사가 있다. 구현이 끝난
항목이 "다음에 할 것"으로 남아 있으면 잡는다. 이 검사가 `app_main.py` 를 읽는다.

분할하면서 `_PLANS` 가 다른 파일로 옮겨 갔다. 스캐너는 `app_main.py` 에서 못 찾았고,
못 찾으면 **"위반 0건"** 으로 조용히 통과했다.

없는 것을 검사하면 위반이 0 이다. 그게 통과와 구분되지 않았다.

`rd_app()` 이라는 다중 파일 리더를 만들어 분할된 조각 전부를 읽게 고쳤고,
새 모듈을 만들 때 **스캐너의 파일 목록에 등재하는 것**을 분할 규칙에 넣었다.

## 검사가 전부 PASS 인데 기능만 죽은 적도 있다

네 건과 조금 다른 다섯 번째가 있다. 이건 검사가 빈 것을 본 게 아니라, **볼 수 없는
것**을 봤다.

분할하면서 재할당되는 전역을 이름으로 import 했다.

```python
from app_utils import _GLOBAL_POOL      # import 시점 값이 복사된다
# 다른 곳에서 global _GLOBAL_POOL 로 재대입해도 이쪽엔 안 보인다
```

`py_compile` 통과, 정적 51항목 PASS, 회귀 38×29 bit-identical PASS.
**전부 초록인데 기능만 조용히 죽었다.** 예열해 둔 워커 풀을 못 봐서 매번 새 풀을
만들었고, 차트 DPI 자동 감지는 150 에 고정된 채로 죽었다. 둘 다 결과값을 바꾸지 않는
종류라 어떤 검사도 걸리지 않는다.

이건 언어 차원의 함정이라 이 프로젝트만의 것이 아니다. 지금은 프로젝트 규칙이 아니라
전역 규칙에 올려 뒀고, 옮기기 전에 `grep "global X"` 로 재할당 여부를 먼저 확인한다.

## 이 건에서 남긴 규칙

네 건의 표면은 다 다르다 — 접근성 API, 골든 케이스, 게이트 범위, 파일 목록.
공통점은 하나다.

> **검사가 무엇을 봤는지를 검사가 말하게 한다.** 몇 개를 순회했는지, 어떤 케이스를
> 밟았는지, 어떤 파일을 읽었는지. 그 숫자가 0 일 때 통과가 나오면 안 된다.

`guard_count` 가 그 장치다. 그리고 이 노트를 쓰면서 다섯 번째를 하나 더 찾았다 —
정적 스캔이 매 커밋 출력하는 커버리지 요약 줄이 `회귀 8×26` 이라고 적혀 있는데,
**같은 실행의 회귀는 38×29 를 돌린다.**

그 줄의 다른 숫자는 전부 계산된 값(`len(results)`·`len(built)`)인데 **회귀만
하드코딩**이었다. 케이스가 8에서 38로 늘어나는 동안 안내는 8에 멈춰 있었고,
매 커밋 초록 옆에 그대로 찍혔다. 검사 결과가 아니라 **검사가 자기를 설명하는 줄**이라
아무도 대조하지 않았다.

골든에서 직접 세도록 고쳤다.

```python
with open('audit_regression_golden.json', encoding='utf-8') as f:
    _g = json.load(f)
reg = f"{len(_g)}×{max(len(v) for v in _g.values())}"   # 38×29
```

**자기가 무엇을 하는지에 대한 검사 자신의 진술도 낡는다.** 그리고 그 진술은
초록 옆에 붙어 있어서 더 안 읽힌다.

> 검사를 만드는 순간이 아니라 **주변이 바뀌는 순간**에 검사가 눈이 먼다.
> 파일이 쪼개지고, 층이 늘고, 위젯이 커스텀이 되면서. 네 건 다 그랬다.
