# 「아무것도 안 깨졌다」만 보는 관문

> 합동 통합방어 시뮬레이터 · 2026-09-05 · [`d04a032`](https://github.com/yim2412/joint-defense-sim/commit/d04a032) … [`cb151bd`](https://github.com/yim2412/joint-defense-sim/commit/cb151bd)

새 기능은 늘 이 경로로 들어왔다.

```
메커니즘 구현 → 단위 검증 → 토글 OFF 면 기존 결과와 bit-identical 확인
             → 회귀 38×29 PASS → "실험적 · 기본 OFF" 로 커밋 → 완료
```

관문이 다섯이나 있고, 마지막 회귀는 고정 시드 결과를 골든과 대조하는 꽤 엄격한
장치다. 이걸 통과하면 완료로 쳤다.

이 관문이 실제로 보장하는 것은 **"기존 걸 안 깨뜨린다"** 하나뿐이다.
**"이 기능이 무언가 한다"** 는 다섯 중 어느 것도 보지 않는다.

OFF 면 bit-identical 이라는 확인은 오히려 반대 방향이다. **아무 일도 안 하는 코드가
가장 쉽게 통과한다.** 함수 몸통을 통째로 지워도 이 다섯은 전부 초록이다.

## 발견은 도구가 아니라 사용자가 했다

> "토글을 켰는데 변화가 0 이다."

레이더 침묵(ARM 이 날아오면 레이더를 끄는 전술)을 켜고 껐는데 결과가 완전히 같았다.
확인해 보니 몇 달째 그 상태였다. 그동안 회귀는 매 커밋 PASS 였다 — **아무것도 안
하는 기능은 회귀를 절대 깨뜨리지 않으니까.**

그리고 옆을 보니 같은 것들이 더 있었다. 능동 소나 EMCON, 레이저, 정찰 드론,
표적 난이도. **전부 같은 경로로 태어났다.**

## 몇 개나 이럴까

엔진이 읽는 토글 중 효과를 한 번이라도 검사받은 것이 몇 개인지 셌다.

```python
# engine_combat.py 가 .get('enable_...') / cfg['enable_...'] 로 소비하는 것
consumed = 50
# audit_effect.py 에 효과 프로브가 있는 것
probes   = 7
```

**43개가 한 번도 검사받은 적이 없었다.** 그 안에 방금 죽은 걸 발견한
`enable_radar_off` 가 들어 있었다.

강제하는 장치가 없어서다. 신기능 체크리스트에 "효과를 확인한다"는 항목이 없었고,
있었더라도 사람 기억에 맡기는 항목은 지켜지지 않는다.

> 🔍 **여기서 수치를 하나 정정한다.** 이 사건을 정리한 계획 문서 머리말은
> *"50개 중 33개"* 라고 적고 있다. 그런데 스캐너 소스 주석이 그 값을 스스로
> 부정하고 있었다 — *"초안 '33개'는 추정치. 실측 = 소비 50 − PROBES 7 = 43."*
> 분모 50 은 2026-09-05 에 다시 재서 맞고, 미커버는 **43** 이다. 계획 문서
> 머리말만 갱신되지 않은 채 남아 있었다.

## 완료의 정의를 바꿨다

순서를 이렇게 잡았다. 규칙이 먼저인 이유는, 무엇을 완료로 볼지가 안 바뀌면
게이트가 정당해지지 않기 때문이다.

```
③ 규칙 개정  →  ① 커밋 게이트  →  ② 발현 카운터  →  ④ 죽은 토글 스캐너
  (사고방식)     (신규 차단)       (진단력 확보)      (기존 43개 청소)
```

**③ 규칙** — "실험적·기본 OFF 로 커밋"은 완성이 아니라 **미완성 상태**로 규정했다.
신규 토글을 커밋하려면 증거 셋을 함께 내야 한다. 각각에 실제 반례가 있다.

| 증거 | 답해야 할 질문 | 죽었던 반례 |
|---|---|---|
| **발현 델타** | ON/OFF 결과가 **얼마나** 다른가 | 레이더 침묵: bit-identical 이었다 |
| **짝 기능** | 값을 하려면 **무엇이 함께 켜져** 있어야 하나 | 레이더 침묵은 **회피 기동이 OFF 면 죽는다** — 함대가 정지하면 조준 좌표 이격이 0 이라 레이더를 꺼도 의미가 없다 |
| **발현 무대** | 어떤 편성·거리·조건에서 **발동**하나 | 레이저: 드론이 5km 에 와야 하는데 함포가 23km 에서 다 잡는다 |

**셋 중 하나라도 못 쓰면 완성이 아니다.** '메커니즘 구현 + 단위 검증'은 필요조건일
뿐이다.

**① 게이트** — `chk_effect_coverage` 를 pre-commit 에 걸었다. 엔진이 소비하는 신규
`enable_*` 에 효과 프로브가 없으면 **커밋 자체가 안 된다.**

기존 43개 때문에 게이트를 켜는 순간 모든 커밋이 막힌다. 그래서 43개를 `EFFECT_DEBT`
라는 **명시적 부채 목록**에 등록하고 유예했다. 조건은 하나다 — **이 목록은 줄어들
수만 있다.** 새 토글을 여기 넣는 건 금지다. 그게 게이트의 존재 이유니까.

## 카운터를 스캐너보다 먼저 만든 이유

여기가 이 트랙에서 제일 잘한 판단이었다.

스캐너로 43개를 전수로 돌리면 델타 0 인 토글이 나올 텐데, **델타 0 은 두 가지를
뜻한다.**

- 메커니즘이 **아예 안 돌았다** — 무대가 없거나 게이트에 막혔다
- 메커니즘은 돌았는데 **결과에 영향이 없다** — 진짜 음성 후보

화면상 둘은 똑같이 생겼다. 구분하려면 "이 기능이 몇 번 발동했는가"를 알아야 한다.
그래서 엔진이 스스로 세게 했다.

```python
self._feat_fire = collections.Counter()
self._feat('radar_off')          # 실제 발동 지점에서 1줄
stats['feature_fires'] = dict(self._feat_fire)
```

제약이 하나 있었다. **카운터가 결과를 바꾸면 안 된다** — RNG 를 소비하면 회귀가
깨진다. 순수 계측이어야 하고, 그걸 회귀 bit-identical 로 확인했다.

카운터 없이 스캐너만 돌렸다면, 델타 0 이 나올 때마다 로그를 뒤지는 삽질을 43번
반복했을 것이다.

## 전수로 돌렸더니 — 진짜 죽은 건 하나였다

첫 전수 스캔이 636초 걸렸다. 그리고 판정이 예상과 달랐다.

부채 43개를 원인별로 A~E 다섯 트랙으로 나눠 청소했다.

| 트랙 | 원인 | 결과 |
|---|---|---|
| A. BMD 지상자산 5개 | **측정 결함** — 토글만 켜고 재고를 0 으로 뒀다 | 짝을 주니 전부 발현 |
| B. 환경물리 4개 | **무대 부재** — 고도별 교전창이 있는 시나리오가 없었다 | 무대 3종 추가하니 발현 |
| C. 흡수형 4개 | 기본 방어가 몫을 다 흡수 | 카운터 시딩 후 2개 상환 |
| D. 대잠·기뢰 3개 | **짝 기능 미충족** — 어뢰가 함정에 근접하는 무대가 없었다 | 짝 무대 만드니 발현 |
| E. 전장 전용 2개 | 단발 교전에서 원리상 미발현 | 전장 프로브로 확증 |

**43 → 0.** 진짜 죽은 기능은 `enable_anti_sam` 하나였다.

그 하나도 "약해서"가 아니라 **발현 경로가 엔진에 존재하지 않아서**였다. 아군 SAM 이
적 함정을 표적으로 잡는 경우에만 발동하는데, 아군 SAM 은 대공 전용이라 적 함정을
표적으로 잡는 경로가 엔진에 아예 없다. `m.target is et` 가 영원히 거짓이다.
코드는 지우지 않고 `EFFECT_DEAD` 라는 별도 상태로 종결했다 — 미래에 짝 기능(SM-6
대함 모드 같은)이 생기면 되살아날 수 있어서.

2026-09-05 에 다시 쟀다.

```
engine_combat 소비 50 · 엔진 5개 합계 60 · PROBES 16
EFFECT_ALIVE 43 · EFFECT_DEAD 1 · EFFECT_DEBT 0 · 미커버 0
```

## 이 건에서 남긴 규칙

> **"기존 걸 안 깨뜨린다"를 확인하는 관문은, 아무것도 안 하는 코드를 가장 쉽게
> 통과시킨다.** 하위 호환 검사·회귀·bit-identical 은 전부 이 성질을 갖는다.
> 무언가 한다는 것은 **따로 증명해야 한다.**

그런데 이 노트의 결말은 "우리가 이만큼 썩어 있었다"가 아니다. 43개를 죽은 기능
목록이라 부르며 시작했는데, 실제로 죽은 건 하나였다.

> **"죽은 것 같다"와 "죽었다"는 다른 판정이다.** 42개는 무대가 없었거나, 짝이
> 꺼져 있었거나, 측정이 틀렸거나, 표본이 모자랐다. 델타 0 을 보고 기능을 지웠다면
> **42개를 잘못 지웠을 것이다.**

부채 목록을 만든 게 결과적으로 가장 값을 했다. 43개를 "나중에 볼 것"이 아니라
**세어서 보이는 곳에 두니까** 하나씩 줄었다.
