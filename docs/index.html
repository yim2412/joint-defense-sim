합동 통합방어 시뮬레이터

한국 해군 이지스 기동전단의 다층 방어 시뮬레이터. 대공·대함·대잠 교전을 확률 모델로 풀고, 몬테카를로로 반복해 요구조건 충족 여부를 판정한다.

Python · PyQt6 · CesiumJS · PyInstaller

저장소 개발 노트 3편 노트 후보 목록 다섯 프로젝트 색인

무엇을 하는가

전술 교전 하나를 푸는 데서 시작해 작전급 캠페인 → 공군 → 육군 → 합동 화력으로 층이 쌓였다. 각 층은 아래층의 산출물만 읽는다.

판정은 눈대중이 아니라 수치다. 같은 편성을 수백 번 굴려 요구조건을 넘는 비율을 내고, 그 결과를 보고서로 뽑는다. 3D 전장 시각화는 그 결과를 눈으로 확인하는 용도지 판정의 근거가 아니다.

주요 기능

  • 교전 모델대공·대함·대잠 — 탐지·요격·명중을 단계별 확률로
  • 몬테카를로같은 편성을 반복 시행해 분포를 낸다
  • 요구조건 판정충족/미충족을 기준과 함께 보고서로
  • 3D 시각화CesiumJS 전장 화면
  • 합동 확장해군에서 시작해 공군·육군·합동 화력으로

개발 노트

커밋마다 회귀와 속성 감사가 도는 저장소인데, 그 관문들이 아무것도 안 보면서 통과하던 이야기가 셋이다. 기능 소개가 아니라 판단 기록이라 «이건 아직 안 쟀다» 도 그대로 적는다.

  1. 01「아무것도 안 깨졌다」만 보는 관문완료의 정의 — 하위 호환 검사는 아무 일도 안 하는 코드를 가장 쉽게 통과시킨다
  2. 02적이 없어서 0이었다측정 설계 — 「죽었다」는 판정이 두 번 다 내 측정 결함이었다
  3. 03아무것도 안 보면서 통과한 검사들검증 사각 — 검사가 눈이 머는 다섯 가지 방식
노트 본문은 저장소에 있다 — 이 페이지는 링크만 건다. 다른 프로젝트의 기록은 개발 노트 색인에.
